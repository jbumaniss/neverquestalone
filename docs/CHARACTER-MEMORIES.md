# Character memories

Character memories keep a small local history for each character and realm. In
the desktop app, open **Settings → Show more → Character memories**.

## Automatic and manual entries

- **Automatically remembered** is generated by the bridge from game state:
  character facts, quests, milestones and sessions. The addon must be installed
  and able to send state; unavailable game facts are not invented.
- **Your memories** are player-authored cards. Type a short preference, goal or
  fact and click **Add memory**. The entry is persisted separately, appears in
  the list, and the input clears only after a successful disk readback.
- **Extra notes** are the older, editable free-form character notes. **Save
  notes** persists the text; **Clear notes** clears only that text, never the
  individual memory cards or automatically recorded facts.
- **Create character** lets you register a character and realm before the first
  game event. It does not replace existing notes. A later game event for the same
  character updates generated facts in that character's folder.

The page reads `memory({ char: "Name-Realm" })` through the desktop's validated
IPC contract. `addMemoryEntry({ char, text })` appends an independent entry and
checks it by ID and text through a new memory read before reporting success.
Extra notes are saved and verified separately.

## Persistence and privacy

Local data is stored in the desktop app's user-data folder under
`memory/<Name-Realm>/`: `entries.json` for memory cards, `notes.md` for editable
text, `character.md`, `quests.md` and `log.md` for generated information. Data is
not removed when the app quits.
Uninstall/Forget all are separate, destructive actions. The AI receives a bounded,
sanitized digest when memory is enabled; identity stays hidden unless enabled.
Do not store credentials or other sensitive information in notes.

There is no background save of unfinished edits in the notes editor: click
**Save notes** to commit them. The notes editor stays filled so it can be edited
again; the separate **Add memory** field clears after success. Reopening the app
must reload cards and saved notes from disk, not an empty draft. A failed Add
keeps its draft and displays a failure instead of a success message.

Automated tests cover manual creation without overwrite, character isolation,
atomic card persistence across fresh backend/API instances, notes isolation,
IPC validation, a fresh renderer instance, and failed-save behavior. The new
card UI still needs a packaged Windows quit/reopen acceptance test.
